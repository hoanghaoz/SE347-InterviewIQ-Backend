## Naming branch

### 1. Standard Syntax

`<type>/<your_module_name>`

### 2. Allowed Types

| Icon | Type         | Description                                                                     | Example                                                  |
| :--: | :----------- | :------------------------------------------------------------------------------ | :------------------------------------------------------- |
|  ✨  | **feat**     | New branch to implement new features                                            | `feat/auth`                                              |
|  🐛  | **fix**      | Branch for fixing bugs or resolving issues                                      | `fix/cart`                                               |
|  ♻️  | **refactor** | Branch for refactoring code without changing existing logic or adding features. | `refactor/product`                                       |
|  📝  | **docs**     | Adds or updates documentation (README, diagrams, etc.).                         | `docs/ci`                                                |
|  🔧  | **chore**    | Maintenance tasks, configurations, or dependency updates.                       | `chore/deps`                                             |
|  🚀  | **perf**     | Code changes that improve performance.                                          | `perf/db: add index to Product table for faster queries` |

### 3. Not to do

You **MUST** not name your branch like this: `fix`, `fix/bug` , `pray-for-god`, `I hope it works`, ...
